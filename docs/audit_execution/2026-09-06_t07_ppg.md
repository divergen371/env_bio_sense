# T07 PPG計測品質・RAW保存 実装記録

日付: 2026-09-06  
対象: P1-10、P1-11

## 結論

MAX30102の設定値だけでなく、FIFOから取り出した各sampleの時刻、低灌流時の有効性、未読・overflowの計数、解析器の二峰性波形への耐性に問題があった。計測品質を修正したうえで、100 HzのRAWをPSRAM経由でSDへ保存し、FRAM checkpointとcommit markerによって電源断から復旧できるPPG1 session保存を実装した。コード、自動試験、PC readerは完了し、実センサー・SD・電源断によるGateを残す。

## 計測品質の修正

- MAX30102はsensor 400 Hz、sample average 4、実効100 Hzとして扱い、FIFO内の各sampleへ10 ms間隔の個別timestampと連続logical indexを付与する。
- `check()`前後のライブラリ内部buffer残量から取りこぼしを計数し、hardware overflow counterも1秒ごとに読取り・clearする。
- 18 bitを超えるsample bitをmaskし、RAW sinkへred、IR、timestamp、logical indexを引き渡す。
- PI 0.2%未満ではHRとSpO2をともに無効化する。過去の正常値はfreshness timeout後に有効扱いしない。
- no finger、calibrating、measuring、unavailableを分離した。sample停止1秒でRAWを無効化し、5秒継続で再初期化、失敗時は30秒backoffで再試行する。
- 解析器の振幅包絡減衰を修正し、短時間で現れる弱い二峰目をdicrotic notchとして除外した。解析器instance間で振幅履歴を共有しない。
- firmwareが実際に使ったred／IR LED電流をsnapshot、PPG1 header、metadataへ記録する。

## PPG1 session保存

- 保存先を`/data/ppg/YYYY-MM-DD/HHMMSS/`とし、`raw.ppg`、`environment.csv`、`metadata.json`の3ファイルを1 sessionとする。
- PPG1はlittle endianの64 byte file header、28 byte block header、8 byte sample、40 byte footerで固定した。block payloadと全sample streamをCRC-32/ISO-HDLCで検証する。
- sensor callbackはSDへ触れずringへ書くだけとした。PSRAM時4096 sample（約40.96秒）、内部RAM fallback時1024 sample（約10.24秒）を確保し、storage taskが最大512 sample／4 KiB単位で排出する。
- RAW、環境、metadataはすべて`.tmp`で生成する。RAWと環境を検証・renameした後、`metadata.json`を最後にrenameしcommit markerとする。
- `environment.csv`へSTART、1秒周期PERIODIC、ENDを保存する。metadataには保存数、drop、FIFO overflow、ring high-water、最大SD書込み時間、環境行数、LED設定、CRCを残す。
- 64 KiB FRAMの既存SD transaction A/B slot末尾の未使用領域へ、二重化したPPG checkpointを追加した。既存ring、event、WALのgeometryは変更していない。
- 起動時はcheckpointとファイルを照合する。末尾が切れたRAWは最後の正常blockまでを別ファイルへコピーしfooterを付け、元ファイルを`.incomplete`として保存する。環境CSVも完全な改行行だけを復旧し、元を保存する。
- 既存の確定済みsessionや不整合な`metadata.json`を自動上書き・削除しない。同秒ID衝突時は既存directoryへ触れず次の秒に再試行する。
- `tools/ppg1_reader.py`を追加し、単体RAWまたはsession directoryについて構造、version、block連番、sample連番、CRC、footer、metadata、環境行数を検証し、CSV抽出できるようにした。

## 実機Gate

1. 有効なUTCと指装着後にsessionが開始し、停止後に3ファイルが所定のdirectoryへ確定することを確認する。
2. PC readerでsession全体を検証し、100 Hzのtimestamp、logical index、block／sample件数、CRC、metadata、環境行数が一致することを確認する。
3. 正常脈波、dicrotic notch、指なし、PI 0.2%境界、体動を実測し、低品質時にHR／SpO2が有効化されないことを確認する。
4. 連続記録を想定時間の2倍以上行い、drop／FIFO overflowが0または実際の欠落と一致し、最大SD書込み時間がring保持時間を超えないことを確認する。
5. SDなし、記録中のSD取外し、低速SD、ring overflow、hardware FIFO overflowを注入し、確定済みsessionを破壊せず原因がeventとmetadataへ残ることを確認する。
6. header、block header、payload、footer、環境CSV、rename前後の17地点以上で各3回電源断し、partialがcompleteとして公開されず、正常prefixだけが復旧され、元ファイルが保存されることを確認する。
7. PSRAM確保失敗時に内部RAM fallbackで記録でき、容量とmemory種別がmetadataに一致することを確認する。
8. MAX30102の通信／sample停止でunavailableへ遷移し、再初期化後に新しい正常sampleだけで計測が再開することを確認する。
9. `environment.csv`にSTART、約1秒周期PERIODIC、ENDがあり、欠損値が空欄かつstatus bitsで説明できることを確認する。
10. SD SPI 4 MHzで上記Gateを満たすことを確認する。測定で不足が示された場合だけ速度変更を検討する。

## 残余リスク

- T08で再帰一覧、検索・絞り込み・並べ替え・ページ分割、複数選択ZIP／削除、PPG状態表示を実装した。実SD上のsessionを使った操作確認はT09の実機Gateで行う。
- 自動試験はbinary codecとFRAM journalの純粋ロジックを網羅するが、Arduino SD filesystemを使うsession managerのfault injectionは実機Gateが必要である。
- RAW sessionは指が`Measuring`の間に自動記録する。保存状態とdrop／overflowはT08のWeb API／UIで可視化した。
