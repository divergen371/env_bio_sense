# SDカードファイル閲覧およびログローテーション実装計画

スマホやPCからSDカードを抜き差しせずにESP32-S3へアクセスしてファイルを閲覧する機能と、長期安定稼働のためのログローテーション機能を実装します。

## 1. 決定事項と基本方針

1. **アクセス方式**: オンデマンドWi-Fi + Webサーバー方式
   - 普段はWi-FiをOFFにして省電力で動作。
   - ボタン操作等でWi-Fi（アクセスポイントモード）とWebサーバーを立ち上げ、ブラウザからアクセスします。
2. **測定継続と排他制御**: 
   - Wi-Fi稼働中・ダウンロード中もセンサの測定とログ記録は止めません（数ミリ秒の遅延は許容）。
   - SDカードへのアクセス（SPI）はMutex等で排他制御します。
3. **1日ごとのログローテーション**:
   - 1日単位（日付が変わるタイミング）で新しいログファイルを作成し、無限に1つのファイルが肥大化するのを防ぎます。
4. **閲覧用ファイルの分離（ロック機構）**:
   - 最新の「現在書き込み中のログ」はWebサーバーから直接開かずロック状態とします。
   - 閲覧リクエストがあった際には、現在書き込み中のログから「閲覧用のスナップショットファイル」を動的に生成（コピー）し、それをユーザーにダウンロードさせることで、書き込み処理と読み出し処理のファイルレベルの衝突を完全に回避します。

---

## 2. システムアーキテクチャの変更点

### 2.1 新規コンポーネントの追加
- **`WifiManager`**: 
  - オンデマンドでのWi-Fi APモードの起動・停止を管理。
- **`WebServerService`**: 
  - `ESPAsyncWebServer` を用いた非同期Webサーバー。
  - SDカード内のファイル一覧（JSONまたはHTML）を提供するAPI。
  - ファイルダウンロード用エンドポイント（`/download?file=...`）。

### 2.2 既存コンポーネントの改修
- **`DataLogger` (ログ記録サービス)**:
  - **ローテーション機能**: RTC（リアルタイムクロック）時刻を元に、日付変更を検知してログファイルを切り替える（例: `log_20231024.csv` -> `log_20231025.csv`）。
  - **スナップショット作成機能**: Webサーバーから要求された際、現在の書き込みバッファをフラッシュし、最新のログファイルを `log_view.csv` のような別名で安全にコピーする機能を追加。
- **`AppController` / タスク分割**:
  - Wi-Fiネットワーク処理がセンサ処理をブロックしないよう、FreeRTOSを利用して「センサー・記録タスク」と「ネットワークタスク」を分割（優先度設定）。
  - SDカード（SPIバス）アクセス用の Mutex 導入。

## 3. 追加ライブラリ (platformio.ini)

- `me-no-dev/AsyncTCP`
- `me-no-dev/ESP Async WebServer`

## 4. ユーザーフロー（想定）

1. **通常時**: ESP32-S3はセンサ計測とSD保存のみを実行（Wi-Fi OFF）。
2. **閲覧時**:
   - ユーザーがESP32-S3の特定のボタン（BOOTボタン等）を押す。
   - ESP32-S3がAPモード（例: SSID `ENV_SENSE_XXXX`）を起動。
   - ユーザーがスマホでসংযোগし、ブラウザで `http://192.168.4.1` にアクセス。
   - ブラウザ上に「過去のログファイル一覧」と「現在の最新ログ」が表示される。
   - ユーザーが最新ログのダウンロードを押すと、裏で閲覧用ファイルが生成されダウンロードされる。
3. **終了時**: 再度ボタンを押すか、一定時間（例: 10分）アクセスがなければ自動でWi-FiをOFFにする。

## オープンクエスチョン（方針決定のお願い）

上記の「ログローテーション」および「閲覧用スナップショット作成機能」を含む実装計画でよろしいでしょうか？

1つ確認事項として、**「1日ごとのログローテーション」には正確な時刻（RTC）が必要**になります。
ESP32-S3は電源を切ると時刻がリセットされるため、時刻をどう取得するかがポイントになります。
- 案A: スマホがWi-Fi接続（閲覧）してきた時に、スマホ側からブラウザ経由で現在時刻をESP32に送信してRTCを合わせる。
- 案B: 別途NTPサーバー（インターネット）に繋ぐ仕組みを入れる（今回はオンデマンドAPモード想定なので少し難しいです）。
- 案C: RTCモジュール（DS3231など）をハードウェアとして追加する。

今回はソフトウェアのみで完結する**「案A（スマホ接続時にブラウザのJSで自動的に時刻同期する）」**を基本線として考えていますが、それでよろしいでしょうか？
