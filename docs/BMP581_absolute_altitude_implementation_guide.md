# env_bio_sense BMP581絶対高度計 実装・作業指示書

## 1. 文書の目的

本書は、`env_bio_sense` の現行BMP5系センサー処理を維持しながら、BMP581の気圧値から絶対高度を算出する機能を実装するための作業指示書である。

実装の中心は、次の4点とする。

1. 周辺気象観測点の海面更正気圧から、センサー設置地点の海面気圧を空間補間する。
2. 既知の設置高度 **13.6 m** を基準に、BMP581個体の加算型気圧オフセットを校正する。
3. 補正済み気圧と補間海面気圧を、現行の温度依存型高度計算式へ入力する。
4. 現行の±0.5 mヒステリシスは、絶対高度を計算した後の表示・配信用出力に適用する。

本書でいう基準高度は、地表標高9.9 mに一般家屋2階相当の3.7 mを加えた値である。

\[
h_{\mathrm{ref}} = 9.9 + 3.7 = \boxed{13.6\ \mathrm{m}}
\]

## 2. 対象範囲

主な確認・変更対象は次のファイルとする。

- `src/drivers/sensors/bmp5_sensor_base.cpp`

- 設定保存層
  - 個体オフセットと校正メタデータの永続化
- 気象データ取得・保持層

## 3. 現行仕様

### 3.1 高度計算に使用する温度

現行実装の温度選択を維持する。

1. `referenceTemperatureC_` が有限値なら、SHT45等から得た外部基準気温を使用する。
2. 外部基準気温が `NaN` 等で使用できない場合は、BMP5内蔵温度 `rawTemperatureC` を使用する。

現行相当の処理は次のとおりである。

```cpp
const float tempForAltitudeC =
    std::isnan(referenceTemperatureC_)
        ? rawTemperatureC
        : referenceTemperatureC_;
```

温度の出所は、計算結果だけでなくログにも記録する。

### 3.2 現行の高度計算式

現行実装では、温度減率を含む次式を使用している。

\[
h = \frac{T + 273.15}{L}
\left[
1 - \left(\frac{P}{P_0}\right)^k
\right]
\]

ここで、

- \(h\)：高度 [m]
- \(T\)：高度計算に使用する気温 [°C]
- \(P\)：センサー設置高度での気圧 [hPa]
- \(P_0\)：センサー位置に対応する海面更正気圧 [hPa]
- \(L = 0.0065\)：温度減率 [K/m]
- \(k = 0.190295\)：現行実装の指数

とする。

本改修では式を別方式へ置き換えない。入力する \(P\) を個体差補正済み気圧へ変更し、\(P_0\) を気圧場補間値へ変更する。

### 3.3 現行のヒステリシス

現行の±0.5 mデッドバンドを維持する。

- 初回有効値：計算高度をそのまま表示高度に設定する。
- `currentAltitudeM - displayAltitudeM > 0.5`：`displayAltitudeM = currentAltitudeM - 0.5`
- `currentAltitudeM - displayAltitudeM < -0.5`：`displayAltitudeM = currentAltitudeM + 0.5`
- 差が-0.5 m以上、+0.5 m以下：表示高度を維持する。

境界値の±0.5 mちょうどでは更新しない。

### 3.4 現行のBMP5およびI²C設定

初期実装では次の設定を維持する。

- ODR：`BMP5_ODR_10_HZ`（10 Hz）
- Pressure OSR：`BMP5_OVERSAMPLING_32X`（32倍）
- Temperature OSR：`BMP5_OVERSAMPLING_2X`（2倍）
- Pressure IIR：`BMP5_IIR_FILTER_COEFF_63`
- Temperature IIR：`BMP5_IIR_FILTER_COEFF_63`
- I²Cクロック：100000 Hz（100 kHz Standard-mode）

## 4. 実装後の処理順序

処理順序は次のとおりとし、順番を入れ替えない。

1. BMP581から温度と気圧を取得する。
2. 外部基準気温またはBMP内蔵温度を選択する。
3. 保存済み個体オフセットをBMP581気圧から減算する。
4. 周辺観測点から得た、現在位置の補間海面気圧を取得する。
5. 補正済み気圧、補間海面気圧、選択温度を現行式へ入力し、生の絶対高度を計算する。
6. 生の絶対高度に現行の±0.5 mヒステリシスを適用する。
7. 生値、補正値、表示値、入力データの品質状態をログおよびWeb/APIへ渡す。

概念上のデータフローは次のとおりである。

```text
周辺観測点の海面更正気圧 ──> 品質確認・空間補間 ──> P0_interpolated ─┐
                                                                        │
外部基準温度 ─┐                                                         │
              ├─> 温度選択 ───────────────────────────────────────────┤
BMP内蔵温度 ─┘                                                         │
                                                                        ├─> 現行高度式
BMP気圧 ──> 個体オフセット減算 ──> P_corrected ────────────────────────┘
                                                                              │
                                                                              v
                                                                  raw absolute altitude
                                                                              │
                                                                              v
                                                                   ±0.5 m hysteresis
                                                                              │
                                                                              v
                                                                    display/log/API value
```

ヒステリシスを気圧値、気圧場補間値、校正残差へ適用してはならない。

## 5. 気圧場補間

### 5.1 入力データの条件

各観測点について、少なくとも次の情報を保持する。

- 観測点ID
- 緯度・経度、または同一座標系の平面座標
- 海面更正気圧 [hPa]
- 観測時刻
- 取得時刻
- データ品質フラグ

使用する値は必ず**海面更正気圧**とする。観測点標高における現地気圧と海面更正気圧を混在させない。

入力値は次の条件をすべて満たす場合だけ採用する。

- 数値が有限で正値である。
- 観測点の品質情報が正常である。
- 設定された許容時間内の観測である。
- 座標と時刻が取得できる。

許容時間は設定値とし、初期値は15分を推奨する。最低3地点を基本要件とする。3地点未満しか有効でない場合は、後述のフォールバック状態へ移行する。

### 5.2 初期実装方式：逆距離加重法

初期実装では、単純で異常判定を行いやすい逆距離加重法（IDW）を使用する。

観測点 \(i\) の海面更正気圧を \(P_i\)、センサー位置からの距離を \(d_i\) とし、重みを次のように定義する。

\[
w_i = \frac{1}{d_i^2}
\]

現在位置の補間海面気圧は次式で求める。

\[
P_{0,\mathrm{interpolated}}
=
\frac{\sum_i w_i P_i}{\sum_i w_i}
\]

実装上は次の点に注意する。

- 距離の単位は全地点で統一する。
- 緯度・経度から距離を求める場合は、既存の平面近似距離計算または測地距離計算を一貫して使用する。
- 距離0による除算を避ける。現在位置が観測点位置と一致すると判定した場合は、その観測点の値を直接採用する。
- 採用地点数、最近傍距離、最遠距離、観測時刻差を品質情報として保持する。
- 補間結果が採用した観測値の最小値から最大値までの範囲にあることを確認する。

4地点以上を利用できる場合でも、初期実装では同じIDWを使用してよい。局所気圧平面 `P0(x, y) = ax + by + c` は将来拡張とし、IDWと実測比較を行わずに切り替えない。

### 5.3 更新とフォールバック

気象データ更新時に新しい補間値を計算し、最後に正常だった値と時刻を保持する。

状態は少なくとも次の4種類に分ける。

- `VALID`：必要地点数、鮮度、品質を満たす補間値
- `LAST_KNOWN`：新規補間はできないが、設定された保持期限内の直近正常値を使用
- `STATIC_FALLBACK`：既存の固定海面気圧を明示的な代替値として使用
- `INVALID`：絶対高度を安全に計算できない

`STATIC_FALLBACK` で得た高度を、品質表示なしで絶対高度として扱ってはならない。`INVALID` の場合は、新しい絶対高度を生成せず、値の無効状態を上位へ通知する。

観測点更新に伴う \(P_0\) の変化はログに残す。初期実装では、気象変化を隠す独自のローパスフィルタを追加しない。段差が実用上問題になる場合は、生高度と気圧場更新の時刻を評価したうえで別改修とする。

## 6. センサー個体オフセット校正

### 6.1 校正モデル

BMP581の加算型個体オフセットを次式で定義する。

\[
\Delta P_{\mathrm{sensor}}
=
P_{\mathrm{BMP}} - P_{\mathrm{expected}}
\]

運用時に高度計算へ渡す補正済み気圧は次式とする。

\[
\boxed{
P_{\mathrm{corrected}}
=
P_{\mathrm{BMP}} - \Delta P_{\mathrm{sensor}}
}
\]

符号を逆にしない。BMP581が期待値より0.4 hPa高く出る個体なら、オフセットは+0.4 hPaであり、運用時にはBMP581値から0.4 hPaを引く。

### 6.2 現行高度式と整合する期待気圧

校正時の期待気圧は、現行高度式を逆変換して求める。別の標準大気式や固定の44330 m式を混用しない。

まず、校正に使用する気温をケルビンへ変換する。

\[
T_K = T_{\mathrm{cal}} + 273.15
\]

現行式

\[
h = \frac{T_K}{L}
\left[
1 - \left(\frac{P}{P_0}\right)^k
\right]
\]

を \(P\) について解くと、期待気圧は次式になる。

\[
\boxed{
P_{\mathrm{expected}}
=
P_{0,\mathrm{interpolated}}
\left(
1 - \frac{L h_{\mathrm{ref}}}{T_K}
\right)^{1/k}
}
\]

ここで、

- \(h_{\mathrm{ref}} = 13.6\ \mathrm{m}\)
- \(L = 0.0065\)
- \(k = 0.190295\)
- \(1/k \approx 5.254999\)

である。

括弧内が正であること、温度と気圧が有限値であることを確認してから計算する。

### 6.3 校正に使用する温度

校正時も運用時と同じ温度選択規則を使用する。

- 外部基準気温が有効なら外部基準気温を使用する。
- 無効ならBMP内蔵温度を使用する。

校正時と運用時で異なる温度規則や異なる定数を使用すると、校正値に計算式の差が混入するため禁止する。

### 6.4 校正手順

1. BMP581を最終設置位置、最終ケース、最終通気構成の状態に置く。
2. 設置高度を13.6 mとして校正モードを開始する。
3. BMP5設定が現行値であることを確認する。
4. 起動直後および設定変更直後はIIR出力が整定していないため、最低60秒の待機期間を設ける。
5. `VALID` 状態の補間海面気圧を取得する。`LAST_KNOWN`、`STATIC_FALLBACK`、`INVALID` では正式校正を開始しない。
6. 強い風、空調吹出口、窓開閉、ケース押圧などの静圧を乱す要因がないことを確認する。
7. 推奨5分間、10 HzでBMP気圧と使用温度を収集する。
8. 各試料の時刻に対応する \(P_{0,\mathrm{interpolated}}\) と温度から \(P_{\mathrm{expected}}\) を求め、残差 `P_BMP - P_expected` を計算する。
9. 無効値と明らかな外れ値を除外し、残差の中央値を初期オフセット候補とする。既存の統計基盤が平均値のみの場合は、上下5%を除外したトリム平均を使用してよい。
10. 補正後の全有効試料から高度を再計算し、受入条件を満たすことを確認する。
11. 合格した場合だけ、オフセットとメタデータを永続化する。不合格時は既存の有効な校正値を上書きしない。

5分間・10 Hzの場合の予定試料数は3000点である。有効試料率80%以上を最低条件とする。

### 6.5 永続化する情報

少なくとも次の情報を一組として保存する。

- 校正データの形式バージョン
- センサー識別情報
- `pressureOffsetHpa`
- 基準高度13.6 m
- 校正開始・終了時刻
- 校正時の平均または中央値の温度と、その温度ソース
- 校正時の補間海面気圧
- 使用観測点IDと観測時刻
- 有効試料数と除外試料数
- 補正前後の平均高度、標準偏差
- ファームウェアバージョン
- 整合性確認用CRC等（保存基盤が対応する場合）

起動時にバージョン、有限値、範囲、センサー識別情報を検証する。校正値が欠損または破損している場合は、0 hPaへ暗黙に置き換えて「校正済み」と表示せず、`UNCALIBRATED` 状態にする。

安全ガードとして、オフセット絶対値が5 hPaを超える場合は、初期実装では校正失敗として扱う。この閾値を変更する場合は、センサー個体差ではなく気圧データ種別、時刻ずれ、設置状態の誤りが原因でないことを先に確認する。

## 7. 運用時の絶対高度計算

### 7.1 計算

運用時の入力を次のように定義する。

```cpp
const float correctedPressureHpa =
    rawPressureHpa - pressureOffsetHpa_;

const float tempForAltitudeC =
    std::isnan(referenceTemperatureC_)
        ? rawTemperatureC
        : referenceTemperatureC_;

const float tempK = tempForAltitudeC + 273.15f;
const float rawAbsoluteAltitudeM =
    (tempK / 0.0065f) *
    (1.0f - std::pow(
        correctedPressureHpa / interpolatedSeaLevelPressureHpa,
        0.190295f));
```

実際の変数名は既存クラスの命名規則に合わせるが、次の値を別々に保持する。

- BMP581が出した未補正気圧
- 個体オフセット
- 補正済み気圧
- 補間海面気圧
- ヒステリシス前の絶対高度
- ヒステリシス後の表示高度

### 7.2 入力検証

高度を計算する前に次を確認する。

- 未補正気圧、オフセット、補正済み気圧が有限値である。
- 補正済み気圧が正値である。
- 補間海面気圧が有限の正値である。
- 選択温度とケルビン温度が有限で、計算可能な範囲にある。
- `correctedPressureHpa / interpolatedSeaLevelPressureHpa` が正値である。
- 校正状態と気圧場品質状態が取得できる。

検証に失敗した周期では、表示高度を異常値で上書きしない。エラー状態と原因を上位へ通知する。

### 7.3 後方互換性

個体オフセットを0 hPa、補間海面気圧を現行の固定 \(P_0\) とした場合、計算結果は現行実装と浮動小数点誤差の範囲で一致しなければならない。

既存の `currentAltitudeM_` がヒステリシス前の値を表している場合は、補正後の絶対高度を代入する。`displayAltitudeM_` は現行どおりヒステリシス後の値とする。変数の意味が異なる場合は、誤用防止のため `rawAbsoluteAltitudeM_` 等へ改名する。

## 8. ヒステリシスの適用位置

ヒステリシスは、絶対高度計算が成功した後、表示・通常ログ・Web配信用の値を確定する直前に適用する。

```cpp
if (!hasDisplayAltitude_) {
    displayAltitudeM_ = rawAbsoluteAltitudeM_;
    hasDisplayAltitude_ = true;
} else {
    const float diffM = rawAbsoluteAltitudeM_ - displayAltitudeM_;

    if (diffM > 0.5f) {
        displayAltitudeM_ = rawAbsoluteAltitudeM_ - 0.5f;
    } else if (diffM < -0.5f) {
        displayAltitudeM_ = rawAbsoluteAltitudeM_ + 0.5f;
    }
}
```

次の場合はヒステリシス状態を初期化し、次の有効高度を初回値として扱う。

- 起動直後
- センサー再初期化後
- 校正値を新規適用または変更した直後
- 長時間の無効状態から復帰した直後
- 高度計算方式または \(P_0\) ソースを運用中に明示的に切り替えた直後

校正処理と受入試験では、必ずヒステリシス前の生高度を評価する。ヒステリシス後の値だけで校正精度を判定してはならない。

## 9. センサー設定の維持・変更方針

### 9.1 初期実装の方針

ODR、OSR、IIR、I²C周波数はすべて現行値を維持する。

理由は次のとおりである。

- 今回の変更対象は基準気圧、個体オフセット、計算パイプラインであり、センサー取得条件ではない。
- 設定を同時に変更すると、絶対高度化による差とノイズ・応答性の差を切り分けにくい。
- 10 Hz、Pressure OSR 32x、IIR 63は、定点高度計としてノイズ抑制を優先する現行意図と整合する。
- I²C 100 kHzは本機能追加の帯域要件を満たしており、変更の必要がない。

### 9.2 変更を検討する条件

設定変更は、初期実装の受入試験後に独立した評価として行う。

- 応答遅延が用途要件を満たさない場合：IIR係数またはODRを評価する。
- 静止時ノイズが受入条件を満たさない場合：OSR、IIR、機械的通気構造、電源ノイズを順に評価する。
- バスエラーや他デバイスとの競合がある場合：I²C波形とバス負荷を確認する。

設定を変更した場合は、校正時と運用時で必ず同じ設定を使用し、再校正と受入試験を行う。

## 10. 実装作業手順

### 手順1：現行コードの確認

- `bmp5_sensor_base.cpp` で、気圧取得から `currentAltitudeM_`、`displayAltitudeM_` 更新までの実際の順序を確認する。
- `referenceTemperatureC_` の更新周期、無効化条件、スレッド安全性を確認する。
- 現行 \(P_0\) の保存場所、単位、更新方法を確認する。
- 気圧がPaかhPaかを確認し、境界で明示的に単位変換する。
- IIR適用済みのドライバー出力を使っていることを確認する。

### 手順2：データ型と状態を追加

- 補間海面気圧と品質状態を受け取るインターフェースを追加する。
- 個体オフセット、校正状態、校正メタデータを追加する。
- ヒステリシス前後の高度を別変数で保持する。
- すべての気圧変数名に `Pa` または `Hpa` を含め、単位を曖昧にしない。

### 手順3：気圧場補間を実装

- 入力データの品質、鮮度、地点数を検証する。
- センサー位置との距離を計算する。
- IDWで `interpolatedSeaLevelPressureHpa` を計算する。
- 状態、採用地点、観測時刻を保持する。
- フォールバックと失効処理を実装する。

### 手順4：校正機能を実装

- 基準高度を13.6 mに固定または設定の読み取り専用初期値として定義する。
- 現行式の逆関数で期待気圧を計算する関数を追加する。
- 校正試料の収集、外れ値除去、代表値計算を実装する。
- 校正値を適用して再計算し、合否を判定する。
- 合格時のみ永続化し、読み戻して一致を確認する。

### 手順5：高度計算パイプラインを変更

- BMP気圧から個体オフセットを減算する。
- 現行の固定 \(P_0\) の代わりに補間海面気圧を渡す。
- 温度選択と指数・温度減率は現行値を維持する。
- 計算結果をヒステリシス前の絶対高度として保持する。

### 手順6：ヒステリシスを接続

- ヒステリシスへの入力を補正後の絶対高度へ変更する。
- ±0.5 mの比較と境界動作を変更しない。
- 校正値変更時と長時間無効後の初期化を追加する。

### 手順7：ログとWeb/APIを更新

- 診断用の生値と、利用者向けの表示値を混同しない名称で公開する。
- 気圧場品質、校正状態、温度ソースを追加する。
- 既存利用者が表示高度だけを参照している場合、そのフィールドの意味と更新周期を維持する。

### 手順8：テスト

- 数式、符号、境界、永続化、フォールバックの単体テストを追加する。
- 記録済みデータまたは模擬入力で統合テストを行う。
- 最終設置状態で校正と実機受入試験を行う。

## 11. ログ仕様

### 11.1 通常計測ログ

通常ログには、少なくとも次の項目を含める。

- 計測時刻
- BMP未補正気圧 [hPa]
- 個体オフセット [hPa]
- 補正済み気圧 [hPa]
- 補間海面気圧 [hPa]
- 気圧場状態
- 採用観測点数
- 使用気温 [°C]
- 温度ソース（外部/BMP）
- ヒステリシス前絶対高度 [m]
- ヒステリシス後表示高度 [m]
- 校正状態
- センサー読み取りおよび計算エラー

10 Hzの全項目を恒常的にテキスト出力すると負荷が高い場合は、内部計算は10 Hzのまま、通常ログを1 Hz等へ間引いてよい。異常発生時と校正時は詳細ログを残す。

### 11.2 気圧場更新ログ

- 更新時刻
- 各観測点ID、距離、海面更正気圧、観測時刻、品質
- 除外した観測点と除外理由
- 補間結果
- 前回値との差
- 状態遷移

### 11.3 校正ログ

- 開始・終了時刻
- センサー識別情報
- 基準高度13.6 m
- 整定待機時間、収集時間、予定・有効・除外試料数
- 校正時の気圧場情報
- 温度ソースと代表温度
- BMP気圧代表値、期待気圧代表値
- 算出オフセット
- 補正前後の高度統計
- 合否と不合格理由
- 永続化および読み戻し結果

## 12. 受入条件

### 12.1 数式と単位

- オフセット0 hPaかつ従来の固定 \(P_0\) を入力したとき、現行高度計算と0.01 m以内で一致する。
- 現行式を使って13.6 mから期待気圧を生成し、同じ温度と \(P_0\) で高度へ戻した結果が13.6 mに対して0.01 m以内で一致する。
- PaとhPaを混在させる経路がなく、テストで100倍の誤入力を検出できる。
- `NaN`、無限大、0以下の気圧を高度値として流さない。

### 12.2 オフセット校正

- 模擬BMP値に既知の+0.4 hPaオフセットを加えた試験で、算出オフセットが+0.4 hPaとなり、補正時に減算される。
- 校正直後、同じ有効な気圧場を使った5分間のヒステリシス前平均高度が13.6 m ±0.3 m以内である。
- 同5分間のヒステリシス前高度の標準偏差が0.5 m以下である。満たさない場合は、アルゴリズムだけでなく設置通気、風、電源、IIR整定を確認する。
- 有効試料率が80%未満、気圧場が`VALID`以外、またはオフセット絶対値が5 hPaを超える場合、校正値を保存しない。
- 再起動後に同一の校正値が読み戻され、校正状態が維持される。
- 失敗した再校正で、直前の有効な校正値が失われない。

### 12.3 気圧場補間

- 全観測点へ同じ海面気圧を与えた場合、補間結果がその値と浮動小数点誤差の範囲で一致する。
- 補間結果が採用観測値の最小値と最大値の間にある。
- 現在位置と一致する観測点がある場合、ゼロ除算せずその地点値を採用する。
- 古い値、異常値、座標欠損、品質不良の観測点を除外する。
- 有効地点が3未満になった場合、定義したフォールバック状態へ遷移し、品質状態をログとAPIへ出す。
- 保持期限を超えた直近値で新しい絶対高度を生成しない。

### 12.4 ヒステリシス

- 初回有効高度がそのまま表示高度になる。
- 差が+0.5 mおよび-0.5 mちょうどの場合、表示高度を更新しない。
- 差が+0.5 mを超えた場合、表示高度が `raw - 0.5 m` になる。
- 差が-0.5 mを下回った場合、表示高度が `raw + 0.5 m` になる。
- 校正精度の評価にヒステリシス前高度を使用している。
- 校正値変更後の最初の有効高度でヒステリシス状態が再初期化される。

### 12.5 現行設定と運用

- ODR 10 Hz、Pressure OSR 32x、Temperature OSR 2x、IIR P/T 63、I²C 100 kHzが維持されている。
- 外部基準気温が有効な場合に優先され、無効な場合にBMP温度へフォールバックする。
- 通常ログまたは診断ログから、未補正気圧、オフセット、補正済み気圧、\(P_0\)、生高度、表示高度、品質状態を追跡できる。
- センサーまたは気象データが無効な期間に、異常高度で表示値を上書きしない。

### 12.6 現地での絶対高度確認

- 正式校正とは別の時間帯に、気圧場が`VALID`の状態で固定設置点を30分以上観測する。
- 30分平均のヒステリシス前高度が13.6 m ±3.0 m以内であることを初期の現地目標とする。
- 目標を外れた場合は、再校正だけで解消しようとせず、観測点の海面気圧種別、時刻同期、空間補間誤差、ケース内外の静圧差、温度代表性を順に確認する。

この現地目標は、BMP581単体精度だけでなく気象観測点からの気圧場推定誤差を含む。運用データを蓄積後、必要に応じて受入幅を改定する。

## 13. 完了条件

次をすべて満たした時点で作業完了とする。

- コードレビューで、処理順序とオフセット符号が本書どおりであることを確認済みである。
- 単体テストと統合テストが成功している。
- 最終設置状態で13.6 m校正に成功している。
- 校正値の保存、再起動後の読み戻し、無効データ時の挙動を実機で確認済みである。
- ログから全入力、補正過程、出力、品質状態を追跡できる。
- 現行BMP5/I²C設定を維持しているか、変更した場合は変更理由、再校正、比較試験結果が記録されている。
- Web/API利用側に、生の絶対高度とヒステリシス後表示高度の違いが明示されている。

## 14. 実装上の禁止事項

- 観測点の現地気圧と海面更正気圧を混在させない。
- 校正に固定44330 m式を使い、運用に温度依存式を使うなど、異なる式を混用しない。
- オフセットの符号を曖昧な `calibration` 名だけで保持しない。
- ヒステリシス後の高度を使って個体オフセットを算出しない。
- 気圧場が無効なときに、品質表示なしで固定 \(P_0\) を絶対高度として使用しない。
- 校正失敗時に直前の有効校正値を上書きしない。
- センサー設定変更と絶対高度化を同じ検証単位で同時に評価しない。
